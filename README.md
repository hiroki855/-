# プリザンター 住所処理スクリプト

プリザンターの住所欄（自由入力）から PostcodeJP API を呼び、郵便番号・都道府県・市区群・丁目・番地〜建物名を自動でセットする画面スクリプト群。

---

## ファイル構成

ファイル名の先頭の番号は **プリザンターに登録するときの読込順** を表す。

| ファイル | 役割 |
| --- | --- |
| `01-address-config.sample.js` | 設定の雛形。**実環境では `01-address-config.js` としてコピーし、APIキーを書き換える** |
| `01-address-config.js` | 実環境の設定（`.gitignore` 対象。リポジトリにはコミットしない） |
| `02-address-formatter.js` | 文字列正規化、郵便番号フォーマット、丁目の漢数字変換、4区分の組み立て、キャッシュ、debounce |
| `03-address-dropdown-ui.js` | 複数候補ドロップダウン、警告/エラーメッセージ表示 |
| `04-address-autofill.js` | エントリ（onChange ハンドラ、API 呼び出し、フィールドセット、インポート時自動解析） |

---

## 前提条件

- プリザンター（画面スクリプトAPIに `$p.getControl` / `$p.set` / `$p.events` を持つバージョン）
- PostcodeJP アカウント（https://console.postcode-jp.com）
- 対象サイトID: **44884**
- フィールド物理名:
  - 住所（全体）: `ClassH`
  - 郵便番号: `ClassN`
  - 都道府県: `ClassY`
  - 市区群: `ClassX`
  - 丁目: `ClassS`
  - 番地〜建物名: `ClassQ`

---

## APIキーの取得手順

1. https://console.postcode-jp.com にログイン
2. 「APIキーを作成」をクリック
3. 命名規則 `pleasanter-{サイトID}-{環境}` に従ってキー名を入力
   - 開発用: `pleasanter-44884-dev`
   - 本番用: `pleasanter-44884-prod`
4. 生成されたキーの「制限設定」→「HTTPリファラ」で許可リファラを登録
   - 開発キー: `http://localhost/*` および 検証環境URL
   - 本番キー: 本番プリザンターURL（例 `https://pleasanter.example.co.jp/*`）
5. 保存し、キー値をコピー

> **重要**: APIキーはブラウザに露出する。HTTPリファラ制限を必ず設定すること。

---

## プリザンターへの登録手順

サイト管理 → スクリプト で、以下の順序で **4本** 登録する。**並び順が重要**:

| 順 | 登録タイトル例 | スクリプト欄に貼る中身 |
| --- | --- | --- |
| 1 | `addr-01-config` | `01-address-config.js`（APIキー差し替え済み）の中身 |
| 2 | `addr-02-formatter` | `02-address-formatter.js` の中身 |
| 3 | `addr-03-dropdown-ui` | `03-address-dropdown-ui.js` の中身 |
| 4 | `addr-04-autofill` | `04-address-autofill.js` の中身 |

すべて「編集画面（新規・更新）」を対象に設定する。

### 本番デプロイ時の運用

- `01-address-config.sample.js` をテンプレートとし、`01-address-config.js` を環境ごとに作成
- 本番反映時は **本番キー** に差し替え
- `01-address-config.js` は Git にコミットしない（`.gitignore` 済み）

---

## トリガー条件

1. 住所欄（ClassH）の `change` イベント（フォーカスが外れた時）
2. **編集画面ロード時**、ClassH に値が入っていて郵便番号（ClassN）が空のとき
   - CSV インポート後にレコードを開いた瞬間に自動で分割される

## トラブルシューティング

| 症状 | 確認ポイント |
| --- | --- |
| 何も起きない | DevTools コンソールに `[address-resolver] イベント登録完了` が出ているか。出ていなければスクリプトが読み込まれていない |
| `ADDRESS_RESOLVER_CONFIG が見つかりません` | `01-address-config.js` がロード前にある or 登録されていない |
| `AddressResolverUtils is not defined` | スクリプトの登録順序が間違っている（01→02→03→04 の順） |
| 「住所検索に失敗しました（管理者へ連絡）」 | APIキー無効、または HTTPリファラ制限の許可URLにアクセス元が含まれていない |
| 「アクセスが集中しています…」 | レート制限（Free: 1回/秒、384回/日）。少し待つか有償プランを検討 |
| 「住所検索がタイムアウトしました」 | `REQUEST_TIMEOUT_MS`（既定5000ms）を超過。ネットワーク状況を確認 |
| 候補ドロップダウンが表示されない | プリザンターのDOM構造変更の可能性。`$p.getControl('ClassH')` の戻り値を確認 |
| レート残数の警告 | `x-ratelimit-remaining-day` が10を下回るとコンソールに警告。日次利用量を確認 |
| 修正したのに反映されない | プリザンター側でスクリプトの中身を **新しいコードで上書き保存** したか確認。ブラウザのスーパーリロード（Ctrl+Shift+R）も試す |

---

## 制約事項

- PostcodeJP `/api/v6/parse` は **プレビュー版**。仕様変更の可能性あり
- APIキーはクライアントに露出するため、リファラ制限は必須
- 各分割フィールドの手動編集 → 住所欄への逆方向集約は本フェーズではスコープ外
- 丁目の漢数字変換は 1〜99 のみ対応（実務上の丁目はこの範囲）
